# vexis

Dashboard for Meteora DLMM rebalance bots. It reads the files each bot already writes and shows health, position, and activity in the browser and as a Telegram Mini App.

## Layout

| Path                 | What it is                                                                  |
| -------------------- | --------------------------------------------------------------------------- |
| `apps/web`           | TanStack Start app (SSR, server functions, Telegram Mini App at `/tg`)      |
| `apps/worker`        | Simulator that writes both bots' file formats; real bots move in next to it |
| `packages/bot-state` | Shared model, journal parsers, health rules, and the server-only file store |
| `bots.json`          | Registry of bots to show. Each `dir` is relative to this file               |
| `docs`               | Local reference docs (Meteora, Jupiter, Effect, TanStack, ...)              |
| `scripts`            | Repo tooling. `fetch-docs.ts` refreshes `docs/`                             |

### Inside `apps/web/src`

```
routes/                 thin route files: search params, loader, SSR mode, layout
features/
  bots/
    bots.functions.ts   createServerFn wrappers, safe to import anywhere
    bots.server.ts      server-only helpers, imported only by bots.functions.ts
    event-tone.ts       client-safe constants
    components/         one component per file (bot-card, health-badge, ...)
  telegram/             Mini App SDK loader and hooks
components/
  ui/                   shadcn/ui, generated by the CLI
  layout/               app shell shared by every route
hooks/                  hooks with no feature of their own
lib/                    framework-free helpers (format, cn)
stores/                 zustand stores, created when the first one is needed
```

New domain work goes in a new folder under `features/`. Import with the `@/` alias, never `../../`. A file ending in `.server.ts` must never be imported by client code; TanStack Start's import protection fails the build if it is. There are no barrel `index.ts` files, so imports point at the file that defines the thing.

## Run

```bash
bun install
bun run dev:worker   # simulated bots write into .state/
bun run dev:web      # http://localhost:3000
```

Checks: `bun test`, `bun run typecheck`, `bun run lint` (Biome; `bun run lint:fix` to apply fixes).

The web app also has zod (schemas), react-hook-form with `@hookform/resolvers` (forms validated by zod), zustand (client state), and effect (Effect 4).

The portfolio pages read a wallet's DLMM positions from Meteora's data API (`dlmm.datapi.meteora.ag`, schema in `docs/meteora/dlmm-openapi.json`) and SOL/BTC prices from Jupiter. Requests follow the API's `x-ratelimit-*` headers, and closed positions are cached per pool until that pool reports a newer close. `/portfolio/$wallet` takes `currency` (`sol` or `usd`), `range` (a preset such as `last-7`, or `custom` with `from`/`to` as `YYYY-MM-DD`), and `pairs`. Meteora's `/portfolio` endpoint only lists pools with a close in the last 365 days, so the page says so when its count falls short of Meteora's all-time total. Optional env: `METEORA_DATAPI_URL`, `JUPITER_API_KEY`.

UI components come from shadcn/ui (Nova style, neutral base, dark). Add or update them with `bunx shadcn@latest add <name>` inside `apps/web`. The generated files in `src/components/ui` are excluded from Biome so the CLI can overwrite them cleanly.

## Deploy

```bash
bun run build
VEXIS_BOTS_FILE=/path/to/bots.json bun apps/web/.output/server/index.mjs
```

The build targets Bun by default. Set `NITRO_PRESET` (for example `node-server`) at build time to target another runtime. The app reads bot files from disk, so it must run on the host the bots write to.

## Routes

| Route                  | SSR mode    | Why                                                             |
| ---------------------- | ----------- | --------------------------------------------------------------- |
| `/`                    | redirect    | Sends visitors to `/portfolio`                                  |
| `/portfolio`           | full        | Wallet search, plus favorite and recent wallets                 |
| `/portfolio/$wallet`   | full        | Overview, Active and Closed tabs from the Meteora DLMM API      |
| `/analytics`           | full        | Placeholder, not built yet                                      |
| `/bots`                | full        | Fleet status ships in the document; 24h tallies stream in after |
| `/bots/$botId`         | full        | Feed with `kinds` and `limit` search params                     |
| `/bots/$botId/journal` | `data-only` | Absolute timestamps need the viewer's time zone                 |
| `/tg`                  | off         | Telegram SDK and `initData` exist only in the Mini App webview  |

## What each bot must write

The dashboard reads the bot's own journal (`journal.jsonl` for tiang, `activity.jsonl` for auto-rebalance) and a `HALT` file if present. Neither journal is written on a healthy idle cycle, so each bot also needs to rewrite `snapshot.json` in its state dir every cycle (write to a temp file, then rename):

```json
{
  "at": 1793426383384,
  "pool": "<pool address>",
  "pair": "HYPE-SOL",
  "activeBin": 4521,
  "position": { "address": "<position>", "lower": 4520, "upper": 4522 },
  "wallet": { "sol": "4.200", "x": "0", "y": "0" }
}
```

Without it the bot shows "No heartbeat". The schema is `Snapshot` in `packages/bot-state/src/model.ts`.
